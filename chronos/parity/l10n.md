# Русский перевод Olympus в Chronos

Эталон — Windows x64 `v0.1.10-nightly.20261116.4774`, исходный коммит `16695c812fffe75e85f8cc3084d2c561aa3ca93f`. На 4774 восстановлены все **5 152 статические замены** из LIVE. Runtime-блок и встроенный словарь совпали побайтно.

Разница в одну строку полностью локализована. В чистом `ThreadDetailsItemsMenu` правило `broad` переводит `Ask anything. @ files, $ skills, / commands`. Затем в Olympus native-правка N03 целиком перезаписала этот диапазон окончательной подсказкой «Спросите что угодно. @ контекст, # задачи, ! поиск, $ скиллы, / команды». Поэтому этот ключ учтён в числе срабатываний на чистом входе и исключён из обязательных 5 152. Статическая подсказка N03 находится в ведении клиентского потока. В DICT переведена именно финальная версия.

Локальная проверка читает оригинальные байты `extract/clean` и `extract/live`. Для каждой из 5 152 записей она проверяет английский и русский диапазоны из `inventory.json`, а также результат двух проходов по соответствующим координатам. Для 13 смешанных файлов чистые диапазоны native переносятся через обе замены в координаты выходного JS. Со стороны LIVE удаляются только описанные диапазоны native, блоки и glue. Только для этих файлов LF/CRLF сравниваются после нормализации. Четыре смешанных файла принадлежат серверу и содержат ноль статических замен.

## Устройство

- В `applyLanguageSetting` отсутствующий, пустой и английский выбор дают `ru`. Любое другое значение передаётся штатной `resolveLocale`. Настройка читается один раз.
- Сборочный плагин запускается в клиентском окружении Vite. Хук `generateBundle` с `order: "post"` видит готовые минифицированные чанки. Сначала обрабатываются литералы с ключом свойства, затем `broad` проходит по результату. Регулярные выражения воспроизводят запрет вложенных фигурных скобок и обратных кавычек в интерполяции. У перевода сохраняются внешние пробелы исходной фразы. Состав `ru-final.json` и трёх списков исключений сверен с файлами Olympus побайтно.
- Ключ свойства определяет одну из трёх таблиц. Элементы `unsafe` разрешены только в явно презентационных свойствах при наличии записи в таблице. Для строк из `blocked-server.json` доступны только явно разрешённые `label` и `presentational`. Таблицы `strict` и `broad` их исключают. Как в Olympus, возможны переводы строк зависимостей в клиентском JS. Автоматического расширения словаря при обновлении T3 нет.
- Сохранён исходный фильтр наличия `jsx`. Каталог GT распознаётся по экспортам нескольких 16-значных идентификаторов перевода, общий чанк контрактов — по сочетанию пар `terminalOpen/terminal.open` и `serverGetConfig/server.getConfig`. Имена минифицированных файлов, их хеши и координаты из описи для перевода не используются.
- По `chunk.moduleIds` плагин находит чанк, содержащий `apps/web/src/main.tsx`, и дописывает LF и точные байты runtime после тела этого чанка. Это тот же порядок исполнения, что в LIVE, включая положение после штатного комментария `sourceMappingURL` на эталонном входе. Инициализация main уже запустила `startup`. Ожидания промиса перед запуском переводчика нет. Импорт в начале main и дополнительный сетевой запрос для словаря не нужны.
- Хеш сборочного правила, таблиц и runtime участвует в расчёте имён выходных чанков. При наличии source map плагин сдвигает сгенерированные колонки вслед за заменами. Проверка хука на переименованном модуле подтвердила попадание runtime только в main, исполнение кода main перед регистрацией обработчика runtime и сдвиг контрольной позиции карты.

## Обновления и CI

В `expected-4774.json` хранится минимальное число вхождений для каждой из 4 267 пар «таблица, исходная строка». Новые совпадения разрешены. Если старый литерал исчез, переехал в другой контекст или минификатор изменил имя переменной внутри шаблона, плагин выводит таблицу, буквальный ключ и фактическое/ожидаемое число. Дополнительные совпадения других строк не скрывают недостачу. Обычно сборка продолжается с предупреждением. При `CHRONOS_L10N_STRICT=1` недостача завершает сборку ошибкой. Ожидается ровно один чанк с исходным main.

В CI отдельная проверка всегда строга и привязана к зафиксированной версии. Workflow запускается вручную или при push в `parity/**`. Он скачивает официальный NSIS из релиза `pingdotgg/t3code`, проверяет SHA-256 установщика, дважды вызывает 7-Zip и извлекает `resources/server.asar`. Скрипт сверяет SHA-256 архива и распаковывает нужные записи по заголовку ASAR в память по одной. Для 118 файлов используются хеши полных файлов LIVE. Для 13 — хеши результата удаления перечисленных в описи диапазонов из LIVE. Для сравнения не нужны копия установленного Olympus, исходники поставщика перевода или установка зависимостей монорепозитория.

### Повторный запуск

Из корня рабочей копии, Node.js 24 или новее. Первая команда сверяет локальные байты по описи, вторая повторяет этап проверки CI на сохранённом официальном архиве.

```powershell
$inventory = 'C:\Users\zulut\.t3\caches\chronos-parity\inventory\asar'
node chronos/scripts/parity/verify-l10n.mjs --inventory $inventory
node chronos/scripts/parity/verify-l10n.mjs --asar (Join-Path $inventory 'extract/windows-4774/resources/server.asar')
```

Оба прогона выполнены локально. Сохранённый официальный установщик также совпал с закреплённым SHA-256 `8302e84605385e3073bf43fbee5e744e081aa41bb42a47b22d49148264cec7d5`. SHA-256 чистого `server.asar` — `8cc741f1b5e7857f3f29b069a4d80d420b2c4ef206d85bed8ad7d37487d37af5`.

## Границы проверки

При проверке общей рабочей копии в `apps/web/src/composerPlaceholder.ts` для native N03 находились 49 буквальных байтов `0x3F` (знаки вопроса). Клиентскому потоку нужно сверить эту константу с окончательной русской подсказкой, приведённой выше. Проверка 5 152 замен исключает N03 по координатам. В runtime DICT правильные байты подтверждены отдельно.

Сверка доказывает эквивалентность на клиентских чанках официального 4774 и порядок работы зарегистрированного хука на контрольном входе. Сборка Chronos с изменениями всех четырёх потоков, запуск её окна, прогон GitHub Actions и покрытие следующего nightly здесь не проверялись. Обычный `vite dev` работает с исходными модулями. Статические замены и добавление runtime выполняются в режиме сборки, включая `build --watch`.

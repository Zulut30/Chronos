### Студия

Удалены API `/api/wp/*`, инструменты `wp_*`, создание сайтов, выбор портов, запуск CLI, локальный PHP-мост, выбор сайта и отправка снимков в медиатеку. Из действующего собранного `app.js` удалены обработчик, выбор сайта и кнопка. Доска продолжает экспортировать PNG для чата. Шрифты и чанки взяты из активной сборки редактора; её соседний архивный каталог был второй копией и не упаковывается.

В `60-studio.js` пункты WordPress создавались безусловно в двух меню, а ошибка API оставляла кнопку нового сайта. Убраны эти пункты, раздел всплывающего списка и его запросы. `92-studio-shell.js` открывает тот же iframe. Уведомления по лицензиям входят в каталог студии и перечислены в корневом `NOTICE.md`.

### Жизненный цикл и данные

После `ElectronApp.whenReady` установленный Chronos запускает менеджер в области жизни `DesktopApp`. У каждого порта своя короткая HTTP-проверка. Проверяются идентификатор службы или порт, а для старого и нового хаба — штатный ответ 401 на запрос без токена. Доступный внешний сервис остаётся под управлением владельца. Занятый порт с неожиданным ответом повторно проверяется через 30 секунд. Только отказ в TCP-соединении позволяет запуск. Если внешний сервис позже освободит порт, Chronos сможет занять его.

Точка входа — `resources/chronos-services/<сервис>/server.mjs`. Electron запускает её через собственный исполняемый файл с `ELECTRON_RUN_AS_NODE=1` и `windowsHide`. Четыре HTTP-службы дополнительно проверяют loopback Host, как в оригинальных studio, mcp-manager и hub. Это ограничивает доступ к запущенным по умолчанию локальным API. CORS, имена маршрутов и заголовки Olympus сохранены для клиента.

Менеджер передаёт `DesktopEnvironment.baseDir` в `CHRONOS_T3_HOME` и `CHRONOS_SERVICES_DATA`; для обычной установки это `~/.chronos`. База находится в `userdata/statev2.sqlite`. Самостоятельный запуск исходников без переменных сохраняет расположения Olympus под `~/.t3`. Старые переменные Olympus для портов и путей хранилищ отфильтровываются при старте из desktop, чтобы переменные другого приложения не перенаправили данные. Для внешнего сервиса сохраняется его собственный профиль. На удалённом хосте воркер использует его локальные пути и окружение.

Менеджер пишет stdout, stderr и события жизненного цикла в `<baseDir>/logs/services/<имя>.log`. После завершения дочернего процесса задержка растёт от 1 до 30 секунд. Перед повторным запуском снова проверяется порт. При выходе отменяются проверки и таймеры и завершаются только собственные процессы. Менеджер не запускает stdio OpenRouter.

### Проверка

- В отдельной копии Electron **44.10.1** из кэшированного Windows-дистрибутива `process.versions.node` вернул **24.22.1**, а `node:sqlite` выполнил `SELECT 1`.
- В Node и в этом Electron прошли восемь тестов воркера и отдельный smoke всех восьми сервисов. Тесты используют временные профили, искусственную SQLite, временные порты и stdio. Проверены создание и чтение доски, обнаружение проекта, библиотека шаблонов, сохранение файла, доступность настроек MCP, оба списка инструментов хаба с разными токенами и отсутствие маршрутов Playground. У интеграций в Windows проверяется health без чтения ключей реестра.
- Исходный Python-воркер и Node-воркер последовательно получили одинаковые входы в одном восстановленном временном профиле. Совпали 51 ответ для Codex/Claude user, project и Claude local, в том числе версии состояния и содержимое копий до изменений. Из сравнения исключены имя/версия интерпретатора и случайные имена каталогов резервных копий. Программа, передаваемая SSH, отдельно проверена локальным Node через stdin.
- В `apps/desktop/src/chronos/services/Sidecars.test.ts` — Vitest с подменой сети и запуска процесса для занятого порта, перехода владения, перезапуска и выхода во время проверки. В CI сборка распаковывает ресурсы из NSIS и ZIP для macOS, сравнивает их с исходным набором и запускает smoke распакованных файлов.
- Отдельная проверка на Windows запустила менеджером временный HTTP-процесс на свободном порту и сверила его cwd, оба пути данных, режим Electron-as-Node и запись stdout в журнал. Второй экземпляр менеджера признал порт внешним. Его остановка сохранила процесс, остановка владельца освободила порт.
- Объём ресурсов без тестов — **21,35 МиБ**. Это объём файлов до сжатия установщиком. Бюджет Windows на 80 файлов основного приложения увеличивается ровно на число исходных файлов сервисов для упаковки. CI отдельно сверяет состав и байты всего каталога сервисов в установщике.
- Проверка установленного интерфейса Windows/macOS, реального SSH и внешних платных API остаётся ручной. Этап переключения профиля и регистраций агентов проводится отдельно.

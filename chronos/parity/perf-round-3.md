# Третий раунд оптимизации Chronos

База — `5f3cfe29e7`. Кандидат — `fb46978d1d`. Проверяется стоимость создания JSX для карточек за пределами видимой области. Прежний код исключает их содержимое из DOM, но родитель уже создал объекты React и передал их в children. Кандидат переносит создание этих объектов внутрь проверки видимости. Фокус, открытое меню и редактирование сохраняют содержимое строки.

## Проверка гипотезы по предыдущему эксперименту

FPS прокрутки ленты извлечён из поля `timeline.fps` файлов 8.json и 16.json артефакта packaged-ui. В обоих пакетах присутствуют #42582 и экспериментальный троттлинг Markdown. Второй пакет дополнительно откладывает создание DOM скрытых карточек. [Исходные измерения](https://github.com/Zulut30/Chronos/actions/runs/45613980606)

| Моки | Без отложенных карточек | С отложенными карточками | Пройдено пикселей |
|---:|---:|---:|---:|
| 8 | 54,94 | 56,82 | 575 → 5021 |
| 16 | 55,00 | 55,61 | 575 → 575 |

Эта серия не воспроизводит падение при добавлении карточек. При восьми агентах существенно различалась даже дистанция прокрутки. Единственная пара не устанавливает причинность и не обосновывает откат сайдбара.

## Проверка текущего кандидата

Пакеты базы и кандидата запускаются последовательно на одной Windows VM в отдельных профилях. Сценарии — 302 строки с 0, 8 и 16 агентами, 1002 строки без агентов. Сравниваются FPS ленты, время первого кадра и готовности, RSS renderer. Стоимость и завершение ответов проверяет стенд. [Парный прогон](https://github.com/Zulut30/Chronos/actions/runs/45640250106) · [Сборка кандидата](https://github.com/Zulut30/Chronos/actions/runs/45640086562)

До получения парных результатов кандидат экспериментальный. Серверные CPU и память этим прогоном не измеряются. Разделение маршрутов уже включено через autoCodeSplitting в Vite. Эффект дополнительных границ загрузки требует отдельного сравнения.

Для Olympus сохраняются предложения перевести 20-speed.js на общий разбор кадров WebSocket и ограничить повторные обходы сайдбара в 93-chat-panels.js. Проверять нужно учёт расхода и скорости каждого агента, перенос строк и работу отделённых вкладок.

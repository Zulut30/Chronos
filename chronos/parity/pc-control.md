Оба инструмента дают агенту один цикл «снимок → действие по ссылке → проверка». Сборка сверяет SHA-256 закреплённых релизных файлов до распаковки. На Windows и macOS вместе с CLI в установщик входят оригинальные лицензии. Указанные размеры — размеры файлов поставщика, измерение памяти приведено отдельно.

В нативном приложении скилл читает дерево через `agent-desktop snapshot -i`, записывает значение через `set-value <ref> --stdin` или вызывает `click <ref>`. Затем запрашивает новый снимок. Для сайта используются `agent-browser open`, `snapshot -i`, `fill`, `click` и `close`. Агент передаёт эти намерения через команду `chronos-pc`, чтобы настройки и подтверждения применялись к каждому вызову.

## Настройки и процессы

В настольном клиенте откройте **Настройки → Общие → Управление ПК**. Выберите приложения и адреса сайтов или разрешите все. Примените настройки. При действии внизу окна появится индикатор, из него можно открыть запросы на подтверждение. Остановить все действия можно через индикатор или Ctrl / ⌘ + Alt + Shift + F12. Настройки сохраняются в профиле Chronos. Журнал хранит последние 100 результатов без текста полей и адресов.

Скилл вызывает локальный командный клиент из окружения backend. Запрос проходит через общий обработчик в Electron main. Проверки настроек, разрешённых целей и подтверждений выполняются перед запуском нативного инструмента. «Каждое действие» включает чтение снимков. «Только опасные» добавляет запрос при открытии или подключении к приложению. В режиме «Без подтверждения обычных действий» разрешены подключение, чтение и первый обычный текст в новом пустом документе системного Блокнота. В обоих последних режимах нажатие кнопки, ввод в произвольное поле, перезапись текста и сохранение всё равно требуют разрешения: дерево не описывает побочные эффекты обработчика. Неизвестное или защищённое веб-поле требует ввода значения в окне Chronos. Только доверенное главное окно принимает решение о запросе. Данные поля передаются через stdin. Отключение разрывает активные соединения. На SSH и WSL управление рабочим столом хоста из этой функции недоступно.

Права на произвольный shell в ОС задаёт сам провайдер. Политика Chronos охватывает его интерфейс управления ПК. Для изоляции произвольного кода провайдера требуется системная песочница.

## Приёмка

На Windows x64 проверялся классический системный Блокнот. Win32-помощник создаёт отдельный рабочий стол через CreateDesktop и запускает там приложение и agent-desktop. Пользовательский рабочий стол остаётся активным. Если в сеансе Windows уже запущен процесс с таким именем, новый запуск через Chronos отклоняется: одноэкземплярная программа может переслать команду существующему окну. Для работы с открытым окном предусмотрен `attach`. После создания процесса помощник ждёт WaitForInputIdle и появления видимого окна с PID запущенного процесса. Тестовая форма сообщает о готовности по событию Form.Shown. Блокнот получил текст через UIA SetValue. Провайдер его меню вернул ACTION_FAILED при попытке Expand. Для временного документа Chronos находит пункт сохранения по Ctrl+S в меню именно созданного окна и посылает ему WM_COMMAND. В smoke результат независимо прочитан с диска. Заполнение двух полей WinForms проверено по содержимому, записанному обработчиком кнопки в тестовом приложении.

Через 250 мс после последней команды на раннере осталось 0 процессов agent-desktop, потребление этого CLI в простое составило 0 байт и 0 мс CPU. За 901 отсчёт положение указателя, активное окно и фокус клавиатуры сохранились. Память самого Chronos, приложения и помощника, удерживающего приватное окно, в этом замере не учитывалась.

При открытой локальной веб-форме рабочий набор daemon agent-browser составил 14,63 МиБ. У 13 принадлежащих ему процессов Chromium суммарный рабочий набор составил 609,54 МиБ. Сумма может дважды учитывать общие страницы памяти. [Методика авторов agent-browser](https://github.com/vercel-labs/agent-browser/blob/v0.44.0/benchmarks/README.md) также отделяет память daemon от памяти браузера.

Веб-тест заполнил обычное и защищённое поля, нажал кнопку и сверил значения на независимом локальном HTTP-сервере. Для защищённого поля сервер получил значение, переданное через интерфейс подтверждения. Его выдачу и взаимодействие с реальными macOS-приложениями этот Windows-тест не проверяет.

## Холодный запуск браузера

В `chronos/pc-control/native.cjs` команда `agent-browser open` запускает Chromium, а отдельная команда `open <url>` получает собственный срок для загрузки страницы. После навигации контроллер сверяет origin. Регрессия в `controller.test.cjs` моделирует 20 секунд запуска и 15 секунд навигации и проверяет однократное открытие URL.

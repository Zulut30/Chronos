# Бюджет производительности Chronos

[Бюджет](../perf-budget.json) задаёт допустимое ухудшение относительно одновременно измеренного main. Для времени, FPS и файлов также действуют абсолютные границы. Для каждой пары workflow берёт готовые Windows-пакеты по полному SHA, при необходимости запрашивает сборку штатным Chronos desktop. Ветки, которые содержат workflow, запускают проверку при push. До включения в основную ветку контрольную серию запускает push в perf/guard с маркером `[perf-audit]` в сообщении коммита.

Одна пара занимает одну Windows VM. Три раунда меняют порядок запусков A/B, B/A, A/B. Каждый сценарий получает новый профиль. Шлюз сравнивает медианы. При заданных относительном и абсолютном допусках действует больший из двух. Отсутствующая серия или функциональная ошибка переводит задание в FAIL. Таблица находится в сводке Actions, исходные замеры и идентификаторы пакетов доступны в артефакте.

| Сценарий | Измерение |
|---|---|
| unused | Пустой десктоп с включёнными по умолчанию функциями. Окна артефактов и управление ПК не открываются. |
| disabled | То же окно после отключения всех переключаемых модулей Olympus. Проверяется фактический набор отключённых модулей после перезагрузки. |
| Оба режима простоя | Private bytes, CPU в процентах одного ядра и число процессов для main, renderer, сервера, хоста Olympus и всего дерева, включая помощников. Сырые файлы содержат также WS и имена образов. После 12 с стабилизации измеряются ещё 12 с. Допуск для добавочного постоянного процесса равен нулю. |
| Claude и Codex | Штатный адаптер запускает закреплённый Windows CLI в пустом профиле. Локальный HTTP-сервер удерживает первый запрос к модели. Измеряется дерево одного CLI вместе с помощниками. Для Codex это первый тред с общим app-server. Личные плагины и удалённая генерация в сценарий не входят. |
| UI | Два подготовленных треда, 300 строк сайдбара, 0/8/16 стримящих ACP-моков. p50 первого кадра и готовности, p95 ввода, FPS ленты под нагрузкой. Стенд проверяет доставку и отображение ответов. |
| Хранилище | 8 моков × 80 абзацев. Разность размеров SQLite + WAL + SHM и трейсов с учётом ротаций в КиБ. Окно checkpoint даёт заметный разброс физического размера. |

Отправная точка для абсолютных порогов интерфейса — [последний опубликованный парный замер UI](perf-ui.md), для диска — [серия с 8 агентами](perf-quick-wins.md) и [разброс WAL](perf-resources-2.md). Для новых сценариев простоя и чистых нативных CLI эталон измеряется заново на том же раннере. Лимиты изменения private memory, CPU и числа процессов указаны в JSON. Точность и применимость к конкретному профилю зависят от набора MCP и активности моделей.

[Команды запуска и разбора](../skills/chronos-perf-guard/SKILL.md). Личные снимки машин хранятся отдельно от репозитория.

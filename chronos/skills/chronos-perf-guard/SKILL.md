# Шлюз производительности Chronos

1. Из checkout Chronos прочитай `chronos/perf-budget.json` и методику в `chronos/parity/perf-guard.md`. Зафиксируй SHA базы и кандидата.
2. Запускай `gh workflow run 430534254 -R Zulut30/Chronos --ref perf/guard -f target=<кандидат>`. Числовой ID работает до включения workflow в main. После слияния используй `--ref main`. Для контрольной пары укажи `target=main`. Для полного аудита четырёх веток передай `-f audit=true`. Push в ветку с workflow также запускает замер. Дождись `gh run watch <id> -R Zulut30/Chronos --interval 60 --exit-status`.
3. В Actions открой сводку задания и артефакт `guard-<ветка>`. Сверь оба SHA в `pair.json`. При FAIL проверь сырой JSON каждого из трёх повторов и сообщения функциональной проверки. Отсутствующая метрика означает незавершённое измерение.
4. Для регрессии сопоставь изменение с diff конкретных SHA. Подтверди причину парой с точечной правкой на той же нагрузке. Для обновления допусков нужна новая серия main ↔ main.
5. Нагрузочный стенд работает на одноразовой VM. Личные профили, настольная установка и SSH-серверы исключены из запуска.

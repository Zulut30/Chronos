# С чего начать в Chronos

Сначала прочитай этот файл **из корня текущего checkout**. Выбирай по запрошенному результату. Обычно достаточно роутера и одного профильного скилла. Третий открывай, когда нужен отдельный шаг приёмки или выпуска. Ссылки на соседние скиллы служат справкой. В установленной копии относительные ссылки разрешай от одноимённого SKILL.md в репозитории.

| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Реализовать функцию, исправить регрессию в коде, найти точку встраивания                     | [chronos-feature](../chronos-feature/SKILL.md)               |
| Изменить экран, тему или клавиатурное управление, добавить настройку во «Внешний вид»        | [chronos-ui](../chronos-ui/SKILL.md)                         |
| Принять готовую правку интерфейса, сравнить экран с Olympus глазами пользователя             | [chronos-ui-review](../chronos-ui-review/SKILL.md)           |
| Проверить поведение установленного пакета, выгрузку Claude, Shift или сохранение настроек    | [chronos-live-verify](../chronos-live-verify/SKILL.md)       |
| Запустить smoke, сравнить снимки, отчёты и русские формулировки с эталоном                   | [chronos-parity-check](../chronos-parity-check/SKILL.md)     |
| Починить непереведённую или склеенную строку, проверить глоссарий                            | [chronos-l10n](../chronos-l10n/SKILL.md)                     |

Для трёх последних строк открой `chronos/skills/<скилл>/SKILL.md` текущей ветки. До интеграции можно прочитать инструкцию без переключения checkout через `git show origin/<ветка>:chronos/skills/<скилл>/SKILL.md`. Проверь, доступны ли указанные в ней инструменты в текущей версии. Для замеров есть [методика стенда](../../scripts/bench/README.md). Для вопроса об устройстве форка достаточно [карты интеграций](../../README.md). Для ревью самих скиллов пройди [валидацию и синхронизацию](../../README.md#скиллы).

## Общие правила

- На слабом ПК и серверах в первую очередь проверяй стабильность, время отклика и память. Новые возможности выключены по умолчанию или загружаются при первом обращении. Модель и глубину рассуждений пользователя сохраняй.
- Сохраняй байты [модулей Olympus](../../../apps/web/src/chronos/olympus/features), минимальные стыки апстрима с `// chronos:` и глоссарий Olympus.
- Зависимости, сборку монорепо и полный typecheck запускай в CI. Локально используй существующие зависимости и точечные проверки по очереди. Если нужен интерфейс, выбери проверенный экземпляр Chronos или [подходящий режим стенда](../../scripts/bench/README.md).
- На серверах и в установленном T3/Olympus разрешено только чтение. Изменения, включая перезапуск, требуют явного согласия пользователя. Береги `~/.t3`, службы на 4517–4524 и чужие процессы. Недостающие секреты запрашивай через `request_secret`. В публичный репозиторий попадают только обезличенные данные.
- Для запрошенных исполнителей используй отдельные ветки и worktree, `codex` / `gpt-6.2-astra`, `reasoningEffort: "xhigh"`. Исполнитель ждёт свой CI в шелле.
- Перед слиянием в main нужны зелёные **Chronos checks**, **Chronos desktop**, **Chronos smoke** по артефакту кандидата (14/14, `require_services=true`, `require_provider=true`) и **Chronos performance guard** с подтверждённой парой main и кандидата. В ежедневной синхронизации нужны также паритет и разбор регрессий.
- Постоянное разрешение на слияние и выпуск есть только у ежедневной синхронизации T3 после всех зелёных проверок. Для остальных задач действуй в пределах запроса. Задание только на отчёт, проверку или ветку завершается этим результатом.

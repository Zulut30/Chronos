# Перед любой работой с Chronos

Открой этот файл из текущей ветки. Выбери по результату задачи один профильный скилл, затем переходи по его ссылкам по мере необходимости. В Claude Code, Codex и Antigravity можно открыть файл напрямую, даже когда список установленных скиллов ещё не обновился. Относительные ссылки в установленных копиях читай от одноимённого файла в репозитории.

| Изменить экран, тему, управление с клавиатуры | [chronos-ui](../chronos-ui/SKILL.md) |
| Принять готовый экран по эталону Olympus | [chronos-ui-review](../chronos-ui-review/SKILL.md) |

Последние три скилла поставляют отдельные ветки. Сначала проверь их наличие в `chronos/skills` текущего checkout. При отсутствии укажи, какой скилл ожидается. Для CI и методики измерений уже доступны [chronos-ci](../chronos-ci/SKILL.md) и [описание стенда](../../scripts/bench/README.md).

## Правила форка

- Стабильность, скорость и потребление ресурсов на слабом ПК и SSH-серверах первичны. Новые возможности по умолчанию выключены или загружаются при первом обращении.
- Сохраняй байты [модулей Olympus](../../../apps/web/src/chronos/olympus/features). Правку апстрима своди к минимальному стыку с `// chronos:`. Русские термины сверяй по глоссарию Olympus.
- Установку зависимостей, сборку монорепо и полный typecheck выполняет CI. На ПК используй точечные лёгкие проверки, установленный Chronos с CDP 9333 или [песочницу](../../scripts/bench/sandbox.mjs).
- Установленный T3/Olympus, `~/.t3`, сервисы на портах 4517–4524 и чужие процессы оставляй в покое. Для SSH-хостов gildra и debian-151 разрешено чтение. Изменения требуют явного согласия. Для ключей используй `request_secret`. Публичный репозиторий содержит только обезличенные данные.
- Исполнителю выделяй отдельные ветку и worktree, `codex` / `gpt-6.2-astra`, `reasoningEffort: "xhigh"`, непрерывную задачу с ожиданием CI в шелле.
- Перед слиянием в `main` проверь на версии кандидата **Chronos checks**, **chronos-desktop**, **smoke 14/14** с `require_services=true` и `require_provider=true`, а также зелёный **chronos-perf.yml**. Пока шлюз из `perf/guard` недоступен или результат отсутствует, слияние ждёт. Ежедневная синхронизация дополнительно проходит паритет и разбор регрессий.
- Постоянное разрешение на слияние и выпуск относится только к ежедневной синхронизации с T3 после всех проверок. Для остальных задач действуют указания пользователя. Теги `chronos-v*` и публикация идут по [chronos-release](../chronos-release/SKILL.md).

Для устройства форка смотри [карту интеграций](../../README.md), для фактов о конкретной сборке — [отчёты](../../parity). При изменении самих скиллов проверь и установи их [по инструкции](../../README.md#скиллы).

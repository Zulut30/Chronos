# Проверка в установленном Chronos

Начни с существующего loopback CDP 9333. В Windows найди слушателя через `Get-NetTCPConnection -State Listen -LocalPort 9333`, сверь его `OwningProcess` с путём `Chronos.exe` и открой `/json/list` на `http://127.0.0.1:9333`. Для запрошенной установки или запуска пакета используй [chronos-ci](../chronos-ci/SKILL.md). Выбери target типа `page` с origin `t3code://app`, проверь название окна, путь процесса и версию пакета. Для действий используй UI через подключённый к этому endpoint CDP-клиент. При отсутствии тестовых провайдеров зафиксируй недоступный сценарий. Offline-провайдер smoke доказывает открытие меню, реальный ответ модели проверяется отдельным ходом.

Используй локальное тестовое окружение Chronos. Для сценария, которому нужен чат, создай пустой временный проект с уникальным именем в новом каталоге TEMP, запиши его путь и идентификатор. Запомни исходные настройки, окружение и текущий экран. Настройка выгрузки действует на все треды Claude выбранного сервера. Для смены интервала нужен изолированный сервер/профиль без пользовательских ходов. [Песочница стенда](../../scripts/bench/sandbox.mjs) импортируется драйверами из [инструкции стенда](../../scripts/bench/README.md). Её ACP-мок подходит для нагрузки, а проверке Claude нужен SDK.

### Выгрузка и возобновление Claude

1. В «Провайдеры → Дополнительно → Выгружать Claude при простое» выставь 1 минуту. В треде A попроси запомнить случайный маркер, дождись ответа. Привяжи PID CLI и время его создания к треду. В треде B оставь активный ход или открытое согласование.
2. Через 60–90 секунд сверь событие `chronos.claude.idle-unloaded` и уход CLI треда A и его стартовых MCP. Тред B должен продолжать работу. Фоновое задание или открытый PTY удерживает процесс. Снимай только сведения о принадлежащих проверке PID.
3. В том же A попроси повторить маркер. Проверь ответ, историю, прежний nativeThreadId и новый PID. Сопоставь `chronos.claude.native-resumed` с выгрузкой по providerSessionId. В конце верни прежний интервал. Дополнительные граничные случаи — в [отчёте о выгрузке](../../parity/perf-idle-unload.md).

### Две модели через Shift

В новом чате выбери первую доступную модель, затем в меню моделей удерживай Shift и щёлкни вторую. Для CDP-клиента используй настоящий модификатор Shift при клике. Проверь, что выбраны обе. Отправь один короткий запрос с маркером через обычный композер, дождись завершения обоих запусков. Сверь модели, два треда и по одному ответу на исходный запрос. Убедись, что следующий обычный выбор возвращает одиночный режим. [Обработка Shift в меню](../../../apps/web/src/components/chat/ModelPickerContent.tsx).

### Внешний вид → Интерфейс

Открой «Настройки → Внешний вид → Интерфейс». Проверь подписи цветного текста и скачивания. В тестовом профиле выключи один модуль и перезагрузи окно. Проверь состояние переключателя и поведение на сообщении тестового чата, затем верни исходное значение и перезагрузи окно. Найди параметр из «Дополнительно» через поиск настроек. Время применения отдельных параметров указано в [описи настроек](../../parity/chat-settings.md). В одноразовом профиле можно запустить `node chronos/scripts/smoke/smoke.mjs --port 9333 --strict-en --verify-chat-settings`.

### Завершение

Дождись окончания созданных ходов. Убери только собственные тестовые треды и проект из боковой панели через меню. Убедись, что проект исчез после обновления. Перед удалением временной папки сверь полный путь с записанным при создании и границей TEMP. Восстанови исходный экран и настройки. В отчёте укажи версию, реально пройденные действия, результат и пробелы. Снимки, идентификаторы тредов и историю чата храни локально вне репозитория.

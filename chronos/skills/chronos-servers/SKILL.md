# SSH и серверный CLI

На серверах по умолчанию разрешено только чтение. Для **gildra** и **debian-151** запрос на метрики покрывает штатную SSH-диагностику. Для измерения используй существующий SSH alias пользователя. В отчёт достаточно включить время, нагрузку, память и агрегаты процессов. Оставь в секрете адреса, аргументы процессов, содержимое окружения, журналы диалогов и учётные данные.

Из Git Bash/WSL с настроенным для этого хоста SSH выполни quoted Bash heredoc. Одинарные кавычки вокруг разделителя сохраняют `$` и переводы строк при передаче удалённому Bash. PowerShell-пайп может изменить кодировку и окончания строк.

```bash
ssh -o BatchMode=yes -o StrictHostKeyChecking=yes gildra 'bash -s' <<'CHRONOS_METRICS'
set -eu
date -u
uptime
free -m
df -h /
ps -eo comm=,pcpu=,rss= | awk '{n[$1]++; cpu[$1]+=$2; rss[$1]+=$3} END {for (p in n) printf "%9d KiB %6.1f%% %4d %s\n",rss[p],cpu[p],n[p],p}' | sort -nr | head -15
CHRONOS_METRICS
```

Для второй машины выбери alias `debian-151`. RSS суммирует резидентную память процессов и может повторно учитывать общие страницы. `pcpu` отражает среднюю долю CPU за жизнь процесса. Для интервального замера, если уже установлен `pidstat`, используй `pidstat -u -r 1 3` и запиши условия нагрузки. Если нет доступа, используй `request_secret` для необходимых данных.

## Какой CLI запускает Chronos

[DesktopSshEnvironment.ts](../../../apps/desktop/src/ssh/DesktopSshEnvironment.ts) получает настройки из окружения **десктопа**. [cliRelease.ts](../../../packages/shared/src/cliRelease.ts) выбирает Linux/macOS-архив для платформы узла. Значение `CHRONOS_SSH_CLI_SOURCE=chronos` при версии Chronos выбирает архив и тег текущей ревизии `chronos-v…`. `upstream` и отсутствие переменной выбирают официальный CLI соответствующей nightly T3. Посмотри [логику установки и определения владельца](../../../packages/ssh/src/tunnel.ts) и [результаты проверки смены источника](../../parity/perf-resources-2.md). Локальная команда Chronos — `~/.chronos/bin/t3` (Windows `t3.cmd`). Глобальная `t3` принадлежит T3.

**Нужно явное согласие** на установку или смену CLI на боевом хосте, развёртывание, управление процессами, изменение конфигурации/БД и перезапуск сервера. Управляемое переподключение после смены источника может скачать архив и заменить работающий процесс. Для проверки выбора URL и запуска используй CI-стенд [ssh-cli.mjs](../../scripts/bench/ssh-cli.mjs). При согласованном переключении зафиксируй хост, прежний источник, версию и готовность резервной копии при миграции. Затем перезапусти собственный десктоп с выбранным источником, переподключи согласованное окружение и проверь версию сервера. Возврат источника сам по себе не откатывает миграции БД.

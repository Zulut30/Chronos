# Исполнители и интеграционная ветка

Делегируй в рамках задачи пользователя. До первого `delegate_task` в треде прочитай `orchestrator_capabilities`, проверь точную модель, доступность `xhigh` и проект Chronos. Если модель или режим недоступны, сообщи об этом. Дочерняя сессия получает только текст задания. Впиши базовый SHA, ожидаемый результат и ограничения прямо в `task`.

```json
{
  "role": "implementation",
  "isolation": "worktree",
  "target": {
    "driverKind": "codex",
    "model": "gpt-6.2-astra",
    "options": { "reasoningEffort": "xhigh" }
  },
  "task": "В Chronos сначала прочитай chronos/skills/chronos-router/SKILL.md. База <SHA>, собственная ветка <ветка>, разрешённые пути <список>. Реализуй <результат>. Приёмка <проверка и наблюдаемый результат>. Работай непрерывно до результата, исправляй ошибки в своей ветке. Пуш только <ветка>, если он разрешён родительской задачей. Жди CI в шелле: gh run watch <id> -R Zulut30/Chronos --exit-status. Тяжёлое только в CI. Сохрани байты Olympus. Оставь в покое установленный T3, ~/.t3, 4517–4524, чужие процессы и worktree. SSH только чтение. Без слияния в main, тегов и релиза. Отчёт по-русски: ветка, SHA, изменения, ссылки на CI, что проверено и что осталось."
}
```

Для каждой задачи задай непересекающуюся область записи. Подготовленный инструментом checkout получает коммит родителя, поэтому зафиксируй нужную базу до запуска. Исполнитель сверяет `git status -sb` и `git rev-parse HEAD`, работает только в выданном worktree и на собственной ветке. Секреты через `request_secret`, в описании задач их не передавай. Сохрани `taskId` и следуй `next` в ответе оркестратора.

## Как объединить ветки

1. Собери от каждого исполнителя имя ветки, точный SHA, состояние CI и границы живой проверки. Сделай fetch разрешённых веток. Сверь, что SHA совпадают с отчётом и изменения укладываются в назначенные файлы.
2. В своём чистом checkout создай `integration/<тема>` от согласованной базы. Вливай проверенные SHA по очереди в порядке зависимостей, например `git merge --no-ff <sha>`. Не переключай чужие рабочие деревья.
3. При конфликте посмотри `git diff --name-only --diff-filter=U` и версии `git show :1:<path>` / `:2:<path>` / `:3:<path>`. Совмести независимые изменения. Сохрани оригинальные байты Olympus, минимальные стыки апстрима, обе нужные проверки workflow. Просмотри итоговый diff, затем `git add -- <paths>` и `git merge --continue`. Продуктовый конфликт с несовместимыми требованиями оставь для решения пользователя.
4. На объединённом SHA повтори проверки взаимодействия и требуемые CI из [chronos-ci](../chronos-ci/SKILL.md). Отдельные зелёные ветки не доказывают работоспособность комбинации. Отчитайся по объединённой ветке. Слияние в main и выпуск регулирует [chronos-router](../chronos-router/SKILL.md).

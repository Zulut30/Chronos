# Исполнители и интеграционная ветка

Постоянное разрешение на полный цикл включает сессии-исполнители. Оркестратор выдаёт им отдельные ветки, проверяет результат и ведёт слияние в main, push и выпуск `chronos-v*`. Для задачи только на объединение готовых веток переходи к разделу о слиянии. До первого `delegate_task` в треде прочитай `orchestrator_capabilities`, проверь точную модель, доступность `xhigh` и проект Chronos. Если модель или режим недоступны, сообщи об этом. Дочерняя сессия получает только текст задания. Впиши базовый SHA, ожидаемый результат и ограничения прямо в `task`.

```json
{
  "role": "implementation",
  "isolation": "worktree",
  "target": {
    "driverKind": "codex",
    "model": "gpt-6.2-astra",
    "options": { "reasoningEffort": "xhigh" }
  },
  "task": "В выданном worktree Chronos первым прочитай chronos/skills/chronos-router/SKILL.md. Сверь HEAD с <SHA>, работай в выданной ветке, разрешённые пути <список>. Реализуй <результат>. Приёмка <проверка и наблюдаемый результат>. Работай непрерывно до результата, исправляй ошибки в своей ветке. Пуш только <ветка>, если он разрешён родительской задачей. Жди CI в шелле: gh run watch <id> -R Zulut30/Chronos --interval 60 --exit-status. Тяжёлое только в CI. Сохрани байты Olympus. Оставь в покое установленный T3, ~/.t3, 4517–4524, чужие процессы и worktree. Серверы и установленный Olympus только для чтения. Без слияния в main, тегов и релиза. Отчёт по-русски: ветка, SHA, изменения, ссылки на CI, что проверено и что осталось."
}
```

Для каждой задачи задай непересекающуюся область записи. Подготовленный инструментом checkout получает коммит родителя, поэтому зафиксируй нужную базу до запуска. Исполнитель сверяет `git status -sb` и `git rev-parse HEAD`, работает только в выданном worktree и на собственной ветке. Секреты через `request_secret`, в описании задач их не передавай. Сохрани `taskId` и следуй `next` в ответе оркестратора.

## Область исполнителя и актуальная база

Одна функция — одна короткая ветка от актуального origin/main. Перед стартом укажи владельца и пути по [карте областей](../../parity/areas.md). Общее изменение CI, упаковки или smoke закрепи за одним исполнителем. Соседние решения передавай через коммиты и согласованные точки подключения.

Перед финальными прогонами исполнитель выполняет `git fetch --no-tags origin main` и `git merge --no-edit origin/main` в своей ветке, разрешает конфликты по карте и пушит результат обычным push. Запиши SHA базы и вершины. При новом merge заново запусти checks, ручной desktop, smoke его артефакта и perf для новой пары. Если база продвинулась до передачи оркестратору, включи свежий main и повтори шлюзы. Независимые активные ветки объединяет оркестратор в integration.

## Как объединить ветки

1. Собери от каждого исполнителя имя ветки, точный SHA, состояние CI и границы живой проверки. Сделай fetch разрешённых веток. Сверь, что SHA совпадают с отчётом и изменения укладываются в назначенные файлы.
2. В своём чистом checkout создай `integration/<тема>` от согласованной базы. Вливай проверенные SHA по очереди в порядке зависимостей, например `git merge --no-ff <sha>`. Не переключай чужие рабочие деревья.
3. При конфликте посмотри `git diff --name-only --diff-filter=U` и версии `git show :1:<path>` / `:2:<path>` / `:3:<path>`. Совмести независимые изменения. Сохрани оригинальные байты Olympus, минимальные стыки апстрима, обе нужные проверки workflow. Просмотри итоговый diff, затем `git add -- <paths>` и `git merge --continue`. Продуктовый конфликт с несовместимыми требованиями оставь для решения пользователя.
4. На объединённом SHA проверь взаимодействие изменений и все четыре барьера [chronos-router](../chronos-router/SKILL.md) по [инструкции CI](../chronos-ci/SKILL.md). Запусти perf из своей ветки и сверь оба SHA в `pair.json`. Если задание ограничено веткой, передай оркестратору SHA и ссылки. В полном цикле оркестратор продвигает main на проверенный коммит, делает обычный push и завершает [chronos-release](../chronos-release/SKILL.md) без отдельного согласования.

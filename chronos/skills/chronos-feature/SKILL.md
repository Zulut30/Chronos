# Функции в Chronos без конфликтов с апстримом

Chronos = апстрим T3 + тонкий слой. Чем меньше строк в файлах апстрима, тем проще каждое
слияние (`chronos-upstream-sync`). Устройство форка — `chronos/README.md`.

## Где писать код
1. **Новые файлы — всегда в своих папках:**
   - веб-клиент: `apps/web/src/chronos/<feature>/…`
   - десктоп (Electron main): `apps/desktop/src/chronos/…`
   - сервер: `apps/server/src/chronos/…`
   - общий код пакета: отдельный файл; если нужен экспорт из `packages/*`, добавляй в конец
     существующего файла блок `// --- chronos: begin … // --- chronos: end ---`
     (как в `packages/shared/src/cliRelease.ts`), а не новую запись в `package.json` пакета.
   - инструменты, скрипты, исходники ассетов, доки: `chronos/…`
   - CI: только `.github/workflows/chronos-*.yml`.
2. **Точка встраивания в файле апстрима — одна-две строки**: импорт + вызов/рендер своего модуля.
   Над правкой комментарий `// chronos: <зачем>`. Логику в файл апстрима не переносить.
3. Не переименовывать и не переформатировать код апстрима, не «чистить заодно» — каждая лишняя
   строка = будущий конфликт.
4. Каждую новую точку встраивания добавь в таблицу «Где Chronos встраивается» в `chronos/README.md`.

## Чего не трогать
appId `com.t3tools.t3code`, userData `t3code-v2`, `~/.t3`, протокол `t3code://`, relay/Clerk
(`.env.example`), мобильный пейринг, имя CLI `t3`, схемы БД и RPC-контракты
(`packages/contracts`). Функции, которым нужны новые RPC/таблицы, сначала обсуди с пользователем:
они расходятся с мобильным приложением и remote-серверами T3.

## Перенос из `chronos/legacy-package/`
Там — бинарные патчи собранного бандла (`client/features/*.js`, `client/l10n`, `services/*`).
Это референс поведения, а не код для копирования:
- DOM-хаки на `MutationObserver` переписывай в React-компоненты в `apps/web/src/chronos/`,
  встраивая их в одну точку (слот, роут, пункт меню).
- Переводы (русский интерфейс): отдельный модуль/локаль в `apps/web/src/chronos/`, подключённый
  одной строкой; посмотри, нет ли в апстриме i18n (`apps/web/src/i18n`) — тогда добавь локаль туда
  отдельным файлом.
- Локальные сервисы (`services/*`) — сначала решить с пользователем: встроить в сервер
  (`apps/server/src/chronos/`) или оставить внешними.

## Проверка
- `git grep -n "chronos:"` — все точки встраивания помечены; `git diff origin/main --stat` — правки
  в файлах апстрима минимальны.
- Локально тяжёлую сборку не гонять (нужны Node 26 + pnpm 12 + vite-plus); проверка —
  `gh workflow run chronos-desktop.yml --repo Zulut30/Chronos --ref <ветка>` и зелёный прогон.
- Работай в ветке `feature/<имя>`, в `main` — по решению пользователя.

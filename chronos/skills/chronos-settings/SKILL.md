# Настройки Chronos

Начни с соседней строки штатного T3 в том же разделе. Сверь заголовок, описание, порядок Tab, размер контрола и поведение при смене окружения. Разницу с апстримом проверяй по тегу версии и истории файла.

- **Компоновка.** Возьми `SettingsPageContainer`, `SettingsSection` и `SettingsRow` из [settingsLayout.tsx](../../../apps/web/src/components/settings/settingsLayout.tsx). У страницы один контейнер прокрутки. Передай название в `title`, короткое пояснение в `description`, элемент справа в `control`. На узкой строке контейнер сам переносит контрол под подпись. Для сворачивания используй [AdvancedSettings](../../../apps/web/src/components/settings/AdvancedSettings.tsx) с `targetIds` или [FoldedSettingsSection](../../../apps/web/src/components/settings/FoldedSettingsSection.tsx).
- **Контролы.** Бери `Switch`, `Select` с его частями, `Input`, `Textarea`, `NumberField`, `Button`, `Dialog` из [компонентов T3 на Base UI](../../../apps/web/src/components/ui). У каждого контрола должно быть доступное имя через связанную видимую подпись или `aria-label`. Для списка, меню, диалога, вкладок, переключателя, слайдера, группы радиокнопок, панели инструментов и дерева используй готовый примитив. Проверь имя и состояние через дерево доступности браузера. Ключ элемента списка бери из его постоянного ID или значения.
- **Тема.** Используй токены T3 для текста, поверхности, границы и фокуса. Стили состояний привязывай к `data-slot`, `data-*` и `:focus-visible`. Инлайн-стили и сгенерированные ID в селекторах исключи. Применяй правила качества [Vercel Labs UI SDK](https://github.com/vercel-labs/ui) в рамках штатного стека T3. Для самостоятельного HTML-артефакта действует [chronos-artifacts](../chronos-artifacts/SKILL.md), там UI SDK рекомендуется отдельно.
- **Текст.** Готовь EN и RU в одном изменении, включая состояния загрузки, ошибки, единицы, поиск и имя кнопки без текста. Пользуйся `gt`/`msg` и каталогами GT либо уже используемой парой EN/RU этой функции. Сохраняй одинаковые переменные и формы ICU. После смены языка проверь длинную подпись, результат поиска и доступное имя. Сверь [глоссарий](../chronos-l10n/SKILL.md).
- **Данные.** Предпочтение устройства помечай `devicePreference`. Для серверной настройки проверь контракт, значение по умолчанию, доступность поля на старом сервере, права и политику администратора. Передавай `serverScoped`, `settingKeys` и сохраняй в выбранное окружение через механизм соседней строки. Проверь два окружения, состояние только для чтения, ошибку сохранения и возврат к последнему подтверждённому значению. Новые ресурсоёмкие возможности выключены по умолчанию. Загружай редактор при открытии, освобождай подписки при закрытии.
- **Поиск и переход.** Добавь стабильный ID и путь в [settingsSearch.ts](../../../apps/web/src/components/settings/settingsSearch.ts), тот же ID на строку или секцию. Учитывай платформу, доступность функции и область. Для нового раздела сверь [SettingsSidebarNav](../../../apps/web/src/components/settings/SettingsSidebarNav.tsx). Панель Olympus регистрируется в [settingsPanels.ts](../../../apps/web/src/chronos/olympus/settingsPanels.ts). [settingsNavigation.ts](../../../apps/web/src/chronos/olympus/settingsNavigation.ts) связывает поиск, фокус, активный пункт и маршрутизатор.
- **Olympus.** Сохраняй файлы [features](../../../apps/web/src/chronos/olympus/features) байт в байт. Монтируй их в [хосте настроек](../../../apps/web/src/chronos/olympus/settingsHost.ts), сопоставляй классы с токенами в области конкретной панели. У iframe своё дерево стилей. Используй его контракт темы. Сохраняй тексты, предупреждения о несохранённых данных и поведение действий.

## Приёмка

1. Сними исходный и исправленный раздел, а также штатную строку T3, из сборок с известным SHA. День и ночь, ширины 1280 и 900, одинаковые масштаб и высота. Используй отдельный профиль и CDP-порт. Для сравнения на чистой Windows собери обе версии через `chronos-desktop.yml` с `portable_windows=true`. Передай в `chronos-smoke.yml` ID кандидата в `desktop_run_id`, исходной сборки в `settings_baseline_run_id` и включи `require_services` и `require_provider`. Для macOS укажи ID исходной сборки с arm64 DMG в `settings_macos_baseline_run_id`. PNG и размеры элементов сохраняются в артефактах `chronos-settings-*`.
2. В видимом Chromium измерь **отрисованный** контраст с учётом прозрачности. Текст ≥ 4,5:1, значимые границы контролов, кольцо фокуса и заливка состояния ≥ 3:1. Проверь обычное, наведённое, выбранное, открытое, недоступное и ошибочное состояние, где они есть. Зафиксируй худшую пару и её элементы в обеих темах.
3. Открой через поиск мышью и Enter, пройди Tab и Shift+Tab, стрелки, Space и Esc. Проверь возврат фокуса, один активный пункт, переполнение, загрузку и отказ сервиса. Для записи используй тестовый профиль и стенд. Проверь сохранённое значение после открытия.
4. В ревью приложи снимки, SHA, результаты [smoke](../../scripts/smoke/README.md) на desktop-пакете этого SHA и perf относительно main. Уточни, какие состояния проверены в пакете и какие доступны только на другой ОС.
